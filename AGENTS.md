# RetailSmart — Execution Rules

- Source of truth: Arquitectura de Solución.
- Work on one clearly defined objective at a time.
- Inspect only relevant files and dependencies.
- Do not explore the entire repository unnecessarily.
- Do not use web search unless blocked by missing technical information.
- Prefer minimal changes and reuse existing modules.
- Run focused tests during implementation.
- Run the full suite only at the final integration checkpoint.
- Do not refactor unrelated components.
- Avoid generating diagrams and lengthy documentation.
- Do not create GCP resources or start billable jobs without approval.
- Do not alter IAM or contracts without approval.
- Commit and push only after successful validation.
- Report results in 8 lines or fewer.
- If blocked, report the exact error and proposed correction.
- Do not repeatedly request confirmation for routine implementation.
